## 1. 구현 요약

1. **데이터베이스 스키마 및 마이그레이션 (`@athena/db`)**
   - `packages/db/src/schema/actions.ts`의 `outreachOpportunities` 테이블에 `(website_id, status)` 복합 인덱스(`outreach_ws_status_idx`)를 추가하고, `packages/db/drizzle/0012_outreach_index.sql` 마이그레이션을 생성 및 로컬 PostgreSQL에 적용했습니다.
2. **코어 Outreach 엔진 (`@athena/core/outreach`)**
   - `discoverOutreachOpportunities`: `responseCitations`(`isBrand = false`)를 `responses`, `prompts`와 조인하여 당사 브랜드를 누락한 채 경쟁사만 언급하거나 높은 인용 비중을 차지하는 외부 제3자 페이지를 집계합니다. 시뮬레이션된 루트 URL(`g2.com`, `techcrunch.com`, `medium.com`, `reddit.com`, `wikipedia.org`, `youtube.com`)을 구체적인 기사/리소스 경로로 정규화하며, `citations`, `citationPct`, `estimatedImpressions`를 산출하여 `outreachOpportunities`에 Upsert합니다.
   - `findOutreachAuthor`: 외부 페이지 도메인 및 URL 슬러그를 분석하여 에디터/파트너십 담당자(`authorName`, `authorEmail`)를 추론 및 저장합니다.
   - `generateOutreachEmailDraft`: 웹사이트 브랜드 정보, 확인된 Knowledge Base 팩트(`kbFacts`), 주요 경쟁사(`competitors`), AI 인용률(`citationPct`), 월간 추정 AI 노출수(`estimatedImpressions`)를 결합한 맞춤형 AEO 피치 이메일 초안을 생성하고, 저자 정보가 비어 있을 경우 자동 보강한 뒤 상태를 `new -> todo`로 승격합니다.
   - `createOutreachOpportunity`, `updateOutreachStatus`, `updateOutreachOpportunity`, `deleteOutreachOpportunity`: 칸반 상태 전환(`new | todo | done`) 및 수동 외부 URL 등록/수정/삭제를 제공합니다.
   - `packages/jobs/src/collection/execute.ts`: 수집 런 완료 시 `discoverOutreachOpportunities`가 자동 실행되도록 연동했습니다.
3. **웹 애플리케이션 (`apps/web`)**
   - `apps/web/src/lib/limits.ts`: `outreachLimiter`(분당 25회) 레이트 리미터를 추가했습니다.
   - `apps/web/src/app/(app)/outreach/page.tsx` & `actions.ts`: RBAC(`admin`/`member` 쓰기 권한 검증), 테넌트 격리(`s.website.id`), 레이트 리미팅, 감사 로그(`audit.outreach.*`)를 갖춘 7개 Server Actions를 구현했습니다.
   - `apps/web/src/components/outreach-kanban.tsx`:
     - **Kanban Pipeline (`New` / `Todo` / `Done`)** 및 **Opportunity Pages Table** 뷰 전환
     - 도메인 필터, 실시간 검색, `+ Add opportunity URL` 폼, `Discover citation opportunities` 버튼
     - 카드별 원클릭 `🔍 Find author`, `✉ Draft pitch`, `→ Todo / → Done` 상태 이동 및 하단 **Outreach Pitch Studio** 상세 편집기

## 2. 적대적 검토 (Adversarial Review) 및 수정 내역

| ID | 심각도 | 발견된 문제 | 조치 및 수정 결과 |
|---|---|---|---|
| **AR-15-01** | High | `discoverOutreachOpportunities` 동시 실행 시 동일 `(websiteId, url)`에 대해 중복 행이 삽입되거나, 사용자가 이미 편집한 `status`, `authorName`, `authorEmail`, `emailDraft`, `notes`가 초기화될 위험 | `websites` 행에 `FOR UPDATE` 잠금을 획득한 트랜잭션 내에서 수행하도록 변경하고, 기존 URL 매칭 시 `citations`, `citationPct`, `estimatedImpressions`만 최신화하며 사용자 편집 필드(`status`, `authorName`, `authorEmail`, `emailDraft`, `notes`)는 보존하도록 수정 |
| **AR-15-02** | High | `createOutreachOpportunity`에서 자사 도메인(own-brand URL)이나 `localhost`/`127.0.0.1`/사설 IP/비정상 스킴(`javascript:`)이 입력될 경우 잘못된 아웃리치 대상이 등록되는 문제 | `normalizeExternalUrl` 검증기를 도입하여 `http/https` 외 스킴, 루프백·사설 IP 대역, 자사 도메인(`website.domain` 및 서브도메인) 입력을 차단 |
| **AR-15-03** | Medium | `apps/web/src/app/(app)/outreach/actions.ts`에서 `s.userId` 참조로 인한 타입 불일치 및 `outreach-kanban.tsx`의 `+ Add opportunity URL` 폼이 `onSubmit`에서 즉시 언마운트되어 React 19 `formAction`의 `FormData` 수집이 누락될 수 있는 문제 | `s.user.id`로 수정하고, `+ Add opportunity URL` 폼에서 `onSubmit` 시 즉시 언마운트하지 않도록 수정하여 폼 제출 안정성 확보 |
