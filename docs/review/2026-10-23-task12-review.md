## 1. 구현 범위 요약

1. **데이터베이스 인덱스 마이그레이션 (`packages/db`)**
   - `packages/db/src/schema/actions.ts`: `insights` 테이블에 복합 인덱스 `insights_website_status_idx (website_id, status, created_at)` 추가.
   - `packages/db/drizzle/0009_insights_index.sql` 생성 및 로컬 PostgreSQL 마이그레이션 적용.

2. **신호 기반 AI 인사이트 엔진 (`packages/core/src/insights/`)**
   - `generateInsights(db, { actorId?, websiteId, days?, now? })`:
     - 최근 `days`(기본 30일) vs 이전 동기간 데이터를 기반으로 3대 핵심 카테고리 인사이트를 결정론적 `signalKey`로 도출:
       1. **`opportunity` (기회 경보)**:
          - `opportunity:source:<rootDomain>`: 브랜드보다 경쟁사가 더 높은 비율로 함께 언급되는 주요 제3자/커뮤니티/파트너 인용 도메인 (최대 3개, 액션 링크 `/sources/<domain>`).
          - `opportunity:uncited-mentions`: 브랜드 멘션률 대비 자사 도메인 인용률 격차가 `15pt` 이상인 경우 비인용 멘션 전환 경보 (액션 링크 `/sources`).
       2. **`gap` (콘텐츠 갭)**:
          - `gap:prompt:<promptId>`: 브랜드 멘션 없이 경쟁사만 추천된 프롬프트 (손실 응답 수·비율·경쟁사명 명시, 액션 링크 `/content`).
          - `gap:topic:<topicId>`: 토픽 히트맵에서 경쟁사가 브랜드를 `10pt` 이상 앞서는 취약 토픽 (액션 링크 `/prompts`).
       3. **`competitor_move` (경쟁사 변화)**:
          - `competitor_move:surge:<competitorId>`: 이전 기간 대비 멘션률이 `+5pt` 이상 급등한 경쟁사 (액션 링크 `/competitors`).
          - `competitor_move:lead:<competitorId>` / `competitor_move:position:<competitorId>`: 멘션률 또는 평균 노출 순위에서 브랜드를 앞서는 경쟁사 (액션 링크 `/competitors`).
          - `competitor_move:brand-drop`: 이전 기간 대비 브랜드 멘션률이 `-5pt` 이상 하락한 경보 (액션 링크 `/olympus`).
   - `listInsights(db, { actorId, websiteId, status?, kind? })`:
     - `prompts:read` 권한 검증 후 상태별(`active`, `resolved`, `discarded`, `total`) 및 유형별(`opportunity`, `gap`, `competitor_move`, `integrity`) 집계 카운트와 필터링된 목록 반환.
   - `updateInsightStatus(db, { actorId, websiteId, insightId, status })`:
     - `prompts:write` 권한 및 테넌트 소유권(`websiteId`) 검증 후 상태 전이(`active | resolved | discarded`) 및 `activity_log` 기록.

3. **주기적·이벤트 기반 실행 (`packages/jobs`)**
   - `generateAllInsights(db)`: 응답이 존재하는 모든 활성 웹사이트에 대해 인사이트 일괄 갱신.
   - Inngest 6시간 주기 크론(`insights-generate-cron`, `TZ=UTC 0 */6 * * *`) 및 온디맨드 이벤트 함수(`website-insights-generate`) 등록.
   - 응답 수집 완료(`executeRun`) 및 경쟁사 변경 재분석 완료(`reanalyzeResponses`) 시 자동 인사이트 갱신 연동.

4. **웹 UI 및 서버 액션 (`apps/web`)**
   - 하드코딩된 `demoInsights` 완전 제거 (`apps/web/src/lib/demo.ts`, `apps/web/src/lib/data.ts`).
   - `/insights` 페이지(`apps/web/src/app/(app)/insights/page.tsx`, `actions.ts`) 및 `InsightsList`(`apps/web/src/components/insights-list.tsx`):
     - 상태 탭(`Active`, `Resolved`, `Discarded`, `All`), 카테고리 필터(`All types`, `Opportunities`, `Content gaps`, `Competitor moves`), 기간 선택(`7d/14d/30d/90d`) + `Refresh insights` 액션.
     - 카드별 정량 지표 배지, 내부 액션 링크(`Inspect source`, `Create content`, `Compare competitors`, `Inspect prompts`), 1-클릭 `Ask Athena` 질문 연동, `Resolve` / `Discard` / `Reopen` 상태 전이 버튼.

## 2. 적대적 검토(Adversarial Review) 및 수정 내역

| # | 발견된 문제 (적대적 검토) | 심각도 | 원인 및 영향 | 수정 조치 |
|---|---|---|---|---|
| 1 | 동시 실행 시 후보 계산 스냅샷 불일치 가능성 | 중 | `buildInsightCandidates`가 트랜잭션의 웹사이트 잠금(`FOR UPDATE`) 외부에서 먼저 실행되면, 동시 실행되는 경쟁사 변경/응답 수집과 레이스가 발생할 수 있음 | `db.transaction` 내부에서 `websites` 행을 `FOR UPDATE`로 잠근 직후 동일한 `tx`에서 `buildInsightCandidates`를 실행하도록 수정 |
| 2 | 경쟁사 삭제·격차 해소 후 구(stale) 활성 인사이트 잔류 | 중 | 이미 해결된 지표 신호나 삭제된 경쟁사의 `signalKey`가 새 후보 목록에서 사라져도 기존 `active` 행이 그대로 남아 있을 수 있음 | 응답이 존재하는 윈도우(`totalResponses > 0`)에서 현재 후보 집합(`candidateKeys`)에 더 이상 존재하지 않는 기존 `active` 신호 인사이트를 자동으로 `resolved` 상태로 전이하도록 수정 및 단위 테스트 추가 |
| 3 | 상태 변경 후 `Refresh insights` 클릭 시 알림 배너 우선순위 역전 | 경 | `InsightsList`에서 `statusState.message || genState.message` 순서로 고정되어 있어, 한 번 `Resolve`/`Discard`를 누른 뒤 `Refresh insights`를 실행하면 이전 상태 변경 메시지가 계속 표시됨 | 마지막 실행된 폼 액션(`lastAction: "gen" \| "status"`)을 추적하여 가장 최근 액션의 결과 메시지가 우선 표시되도록 수정 |
