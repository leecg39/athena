## 1. 구현 내역 요약

1. **통합 관측 및 텔레메트리 스토어 (`apps/web/src/lib/telemetry.ts` & `/api/telemetry`)**:
   - **PostHog 이벤트·세션 리플레이·서베이 수집**:
     - `sanitizeTelemetryProperties`: 이벤트 속성 내 `password`, `secret`, `token`, `api_key`, `authorization`, `cookie`, `ath_...` 값을 자동으로 `[REDACTED]` 또는 `[REDACTED_API_KEY]`로 마스킹.
     - `recordSessionReplaySnapshot`: `maskedInputs: true` 및 `maskedSelectors: ["[data-ph-mask]", "input[type=password]", "code"]`를 강제 적용.
     - `recordProductSurveyResponse`: 인앱 NPS/제품 피드백 서베이(0–10점, 카테고리 `nps` / `feature_request` / `ux_feedback` / `data_accuracy`) 수집 및 PostgreSQL `activity_log` 감사 로그 기록.
   - **Vercel Analytics & Speed Insights (`apps/web/src/app/layout.tsx`, `recordWebVitalMetric`)**:
     - `<Analytics />` 및 `<SpeedInsights />` 연동 + Core Web Vitals (`LCP`, `INP`, `CLS`, `FCP`, `TTFB`) 등급(`good` / `needs-improvement` / `poor`) 판정 및 모니터링.
2. **OpenTelemetry OTLP 트레이싱 (`apps/web/src/app/api/otel/traces/route.ts`)**:
   - OTLP/JSON (`resourceSpans` 표준 포맷 및 단일 `spans` 배열) 및 OTLP/Protobuf 수집 지원.
   - `withTracedSpan`: 서버 작업 구간의 지연 시간(`durationMs`), 상태(`OK` / `ERROR`), 속성을 자동 계측하여 트레이스 링 버퍼에 기록.
   - `validateOtlpCollectorEndpoint`: 외부 OTLP 컬렉터 포워딩 시 클라우드 메타데이터(`169.254.169.254`, `metadata.google.internal`) 및 비-HTTP(S) 스킴을 차단하는 SSRF 가드 적용.
3. **CSP 위반 리포트 수집기 (`apps/web/src/app/api/csp-report/route.ts`)**:
   - `application/csp-report` (`{"csp-report": ...}`) 및 Reporting API v1 (`[{"type":"csp-violation","body":...}]`) 이중 파싱.
   - `sanitizeCspUri`: `document-uri`, `blocked-uri`, `source-file`에서 쿼리 스트링(`?token=...`)과 해시 프래그먼트(`#...`)를 제거하여 민감 토큰 유출 방지.
4. **React Email 트랜잭셔널 이메일 템플릿 5종 (`packages/emails/src/index.tsx`) & 랜딩 페이지 (`/landing`)**:
   - `WeeklyReportEmail`, `InviteEmail`, `WelcomeOnboardingEmail`, `OracleAlertEmail`, `BillingReceiptEmail` 5종 컴포넌트 및 `EMAIL_TEMPLATE_CATALOG` / `renderEmailTemplateHtml` 구현.
   - `/settings/observability` 운영 콘솔 및 `/landing` 자체 브랜드 랜딩 페이지 구축.

## 2. 적대적 검토(Adversarial Review) 및 수정 사항

| # | 발견된 취약점 / 엣지 케이스 | 심각도 | 수정 내용 |
|---|---|---|---|
| 1 | 기존 `PostHogProvider`에서 `session_recording: { maskAllInputs: false }`로 설정되어 있어 API 키나 비밀번호 입력값이 세션 리플레이에 평문 녹화될 위험 | **High (Privacy / Secret Leak)** | `PostHogProvider` 및 `recordSessionReplaySnapshot`에서 `maskAllInputs: true`와 `maskTextSelector: "[data-ph-mask]"`를 강제하도록 수정 |
| 2 | `/api/otel/traces` 및 `/api/csp-report`에서 요청 본문 크기 제한이 없어 대용량 페이로드 전송 시 메모리 고갈(DoS) 가능 | **High (DoS)** | `MAX_OTEL_BODY_BYTES = 256KB`, `MAX_CSP_BODY_BYTES = 32KB` 상한을 적용하고 초과 시 즉시 `413 Payload Too Large` 반환 |
| 3 | CSP 리포트의 `document-uri`나 `blocked-uri`에 쿼리 파라미터(`?token=...`, `?secret=...`)가 포함된 채로 수집될 경우 로그를 통해 민감 정보 노출 가능 | **Medium (Info Disclosure)** | `sanitizeCspUri`를 통해 모든 CSP URI에서 `?` 쿼리 문자열과 `#` 프래그먼트를 제거한 뒤 저장 |
| 4 | 이메일 템플릿 CTA 버튼 URL에 `javascript:` 또는 `data:` 스킴이 주입될 경우 이메일 클라이언트 XSS 위험 | **Medium (XSS)** | `safeEmailHref`로 `http:` / `https:` 프로토콜만 허용하고 `escapeEmailHtml`로 동적 텍스트를 이스케이프 처리 |
